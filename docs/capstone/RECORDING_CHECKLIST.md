# Recording and submission checklist

## Story and timing

- [ ] 0:00 hook is the problem/result, not the presenter's name.
- [ ] Name, TrackFlow, automated process, and one-line solution follow the hook.
- [ ] Problem identifies the affected operators and business value.
- [ ] Live demo shows the real TrackFlow RFP workflow and observability.
- [ ] AI technologies are explained through value, not listed without context.
- [ ] Hard problem, “X over Y because…” trade-off, and proudest decision appear.
- [ ] All three exact Q&A questions are answered truthfully in complete sentences.
- [ ] Total is approximately five minutes.

## Recording quality

- [ ] Landscape, 1080p if possible, full-resolution screen capture.
- [ ] Face a light source; no bright window behind the presenter.
- [ ] Use a headset/earbud microphone in a quiet room.
- [ ] Presenter is visible for the introduction, engineering section, and Q&A.
- [ ] Presenter looks into the lens for Q&A.
- [ ] Two seconds of silence before and after every Q&A answer.
- [ ] Practice the full pitch aloud at least twice before the recorded take.

## Required package

- [ ] `FirstnameLastname-TrackFlow.mp4`
- [ ] `FirstnameLastname-TrackFlow-description.txt`
- [ ] `FirstnameLastname-media-release.pdf`, or the explicit cohort-private
      opt-out file allowed by the assignment.
- [ ] All three files are in one permanent Drive/OneDrive-style folder.
- [ ] Sharing is “anyone with the link can view” or explicitly grants instructor
      access; no request-access wall.
- [ ] Folder link was copied through **Share → Copy link**, not the address bar.
- [ ] Link opens in a logged-out/private browser and has no expiry.
- [ ] Permanent folder link is added to the root repository README.
- [ ] The same folder URL is submitted in the instructor-designated LMS field.
